Inverse Design Challenge

Here are ten force curves measured on this rig, each with the pattern that produced it. Your task is to find a different pattern that reproduces one of these curves. Many patterns give very similar curves, so there is no single right answer. You can design your pattern in the editor or with your own code. The rig then tests it and your score goes on the leaderboard.

Targets and leaderboard

Each target below is a measured force curve. Its pattern is shown next to the chart but is not in the data set, and an entry that simply copies it is refused. When you submit an entry, the rig tests it and scores it by how closely its curve matches the target. The score is the root-mean-square (RMS) difference between the two curves in newtons. The difference in displacement at 20 N and the number of cells that differ from the target's pattern are shown alongside.

Standard Data Split

To make entries comparable, please train and evaluate on the same data. The benchmark set is the first 20,000 runs of the data set (rows 0 to 19,999). They are divided once, by a fixed random shuffle, into 15,000 training rows, 2,500 validation rows and 2,500 test rows. Download the three index files and use them as they are. Train only on the training rows, use the validation rows to tune your model, and report your accuracy on the test rows. The ten challenge targets are separate: their patterns are in none of these sets.

Download the Split

A zip with three text files, one row number per line. The row numbers are those of the data set download (codeData.npy, dataData.npy, maxData.npy).

  • train.txt: training rows
  • validation.txt: validation rows, for tuning
  • test.txt: test rows, for reporting
  • README.txt: the rules and how the split is made

The same files are inside the data set download, in its split folder.

How the Split Grows

The data set grows with every test, so the benchmark grows in steps of 10,000 runs. Each block of 10,000 rows is shuffled once with a fixed seed and divided into 7,500 training, 1,250 validation and 1,250 test rows. Benchmark 20k uses the first two blocks, Benchmark 30k will use the first three, and so on.

A row's role never changes when the benchmark grows, so a test row of Benchmark 20k is still a test row in every later version. State the benchmark version you used (for example "Benchmark 20k") with your method.

Loading it in Python: train = np.loadtxt("train.txt", dtype=int), then codeData[train], dataData[train] and maxData[train].

Work Offline: Download the Targets, Upload Your Entries

For your own algorithms: download all ten target curves, design patterns on your computer, then upload them as a zip. Each pattern is tested on the rig and scored against its target, just like an entry made in the editor.

Step 1

Download the Target Curves

A zip with the ten targets in the same format as the data set:

  • targets_dataData.npy: 10 × 200 force curves, stored as 2F/20 N − 1
  • targets_maxData.npy: displacement at 20 N, mm
  • targets.csv: which row is which target
  • targets_curves.csv: the same curves as displacement (mm) and force (N)
  • targets_patterns.txt: the pattern of each target
  • README.txt: formats, scoring and how to submit

Step 2

Upload Your Entries

One .zip with two text files, at most one pattern per target (up to 10):

patterns (or patterns.txt)
One pattern per line: 105 digits of 0 and 1, bottom row first, 1 = insert.
targets (or targets.txt)
One target per line (T1 … T10), in the same order as patterns.
